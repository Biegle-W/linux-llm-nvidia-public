# Wan 1080p VRAM and Raylight repair — November 5, 2026

The previous failed 1080p screens remain dated evidence in [the original report](COMFY-VIDEO-720P1080P-20261105.md). This follow-up fixes the native path's single-card activation pressure and Raylight's mismatched guidance execution on the unequal 12/10 GB pair. CPU execution-weight offload remains disabled.

## Implementation and diagnosis

The native 1080p graph places the first 16 of 30 Wan transformer blocks and the input/output layers on GPU0; the final 14 blocks stay resident on GPU1 alongside the VAE. Activation transfers cross the GPU boundary; model weights do not move to CPU for inference. The remote wrapper explicitly enters GPU1's CUDA device context for custom fused kernels, then returns the final block output to GPU0 for the head. The remote weights are deliberately outside the GPU0 model patcher's relocation tree and remain strongly owned by their block wrappers. This is a narrow plain-Wan workflow, not a general LoRA/ControlNet splitter.

Both 1080p paths execute positive and negative guidance branches individually, leaving Comfy's guidance combination unchanged. Unused allocator segments are released between branches; live GPU tensors remain resident. Explicit GPU VAE decoding uses 256-pixel tiles, 64-pixel overlap and temporal 16/4 tiles.

Raylight's old failed collectives had payloads differing by a factor of two and different sequence counts. Comfy's guidance batching depends on each rank's independently measured free VRAM, so the unequal cards can choose different batch shapes. Deterministic individual guidance passes eliminate that decision. This diagnosis is consistent with the recorded payload mismatch and successful repeated renders; it is not an instrumented proof of every internal collective dependency. NVIDIA's multi-communicator launch-order option is also enabled, but an ordering-only retry still failed. The successful remedy adds deterministic guidance passes; the 60-second NCCL timeout was not raised. [NVIDIA launch-order documentation](https://developer.nvidia.com/blog/improved-performance-and-monitoring-capabilities-with-nvidia-collective-communications-library-2-26/).

The Raylight patch is tracked and hash-pinned against the unchanged upstream commit, including the earlier GPU-resident ignored-parameter correction. Torch, ComfyUI, Raylight, Mesh, GGUF, drivers and checkpoint versions remain pinned. Native 512×288/720p graphs and Raylight 512×288 guidance behavior remain unchanged.
