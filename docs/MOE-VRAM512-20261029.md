# MoE 512 MiB reserves and dense RAM-cap removal — October 29, 2026

GLM and both DeepSeek engines were tested with 512 MiB native VRAM allocation reserves on the 45.55 GiB usable reduced-RAM machine. Only fully passing candidates are applied. HyperQwen and SGLang no longer have 30/36 GiB worker RAM caps; all six profiles retain the 2 GiB host-available floor.

The pass gate requires JSON, arithmetic, supported images, near-window retrieval, at least 90 seconds of continuous generation, a fresh-process reload and normal guarded loading. Failed candidates keep the original 2,048 MiB reserve. Context, cache settings, weights, precision and runtimes were unchanged. Native allocation reserves are separate from the dense 512 MiB minimum-free-VRAM stop.

The saved fixture method uses one 64-token warm-up and three measured 128-output-token requests with about 2.2K input, temperature 0 and top_p 1. Prefill is native timing; TTFT and decode use client SSE. Loading/warm-up are excluded; OS file cache is not flushed. Prior selected results are historical comparisons, not a fresh paired 2,048 MiB control. Rejected screen rates never replace selected results.

## Dense RAM caps removed; other guards retained

Normal HyperQwen and SGLang each passed JSON and actual readbacks of MemoryHigh=infinity, MemoryMax=infinity and MemorySwapMax=infinity; memory.high, memory.max and memory.swap.max read max. The recognized dense launcher, supervisor and native preflight all accept this approved configuration while retaining cgroup ownership checks. Foreign test commands retain bounded defaults. MoE workers retain their selected 44/48 or 46/48 GiB budgets. No CPU weight offload was enabled.

The 2 GiB host floor, 82 C thermal stop, three-reading hysteresis, dense 512 MiB free-VRAM floor, active swap/PSI/telemetry guards, swappiness 60, concurrency one and 600-second idle unload remain. Forty-two CPU checks passed. Dense normal-route checks are functional checks, not new speed/context benchmarks.

## Resource evidence and operational handling

Sampled RAM/swap/VRAM/temperature extrema and tested token counts are in the numeric evidence. Cgroup memory includes reclaimable file cache. Samples do not establish instantaneous extremes, exact maximum inputs were not retested, and bounded qualification does not establish multi-hour reliability.

Two initial GLM/Strata requests failed before loading because the long-running router cached the old validator and rejected uncapped dense metadata. Those setup failures are retained separately. One router reload occurred only while idle with no workers, under an owned temporary reservation; DSH was preserved. Corrected trials did not repeat the genuine Maya failure. Upgrades must load the new validator at a safe idle boundary.

Final router is idle, workers stopped and GPU reservation absent; no fallback was restored. Preimages and credential-redacted configs are archived privately. Raw credentials, telemetry and ownership/session data remain local. Full-RAM cache restoration requires explicit human confirmation plus Linux capacity verification and guarded loading checks. Preserve the separately approved dense cap removal, host reserve and qualified VRAM selections unless the human revises them; no timer trigger.
