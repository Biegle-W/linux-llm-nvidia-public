# TensorFold entry and Flash-Next IQ1_S — November 4, 2026

TensorFold is now a separate enabled entry, `qwen27b-tensorfold`, in the normal authenticated API and DSH NVIDIA server provider. It uses the same tested Mia EXL3 2.0bpw target, TensorFold 1.2.2, DFlash2 quantized to 4-bit at runtime and automatic context copies. The HyperQwen/SGLang entries and default selection are preserved. Existing larger RAM/offload profiles remain disabled; the host still has temporary 32 GB RAM.

Select it in DSH, through the router, or with `./scripts/start_model.sh qwen27b tensorfold`. Its display name explicitly identifies the quant, drafter/copies and 12K context. DSH was reloaded for the entry; the API/hub stayed active during that reload. After the short check the worker was unloaded, with no fallback preload.

## Flash-Next IQ1_S with SSD n-gram table: passed

The requested new Unsloth v3.1 revision is `d96201194f103c906994f283f504209dc8d2a10c`. All three IQ1_S shards passed publisher LFS SHA256 verification on NVMe SSD: 66.379 GB total, including the 28.800 GB IQ4_NL n-gram table. This was an isolated new candidate; the disabled older IQ3 profile and saved full-RAM cache choices were preserved. Flash-Next IQ1_S was not added to the enabled menu by this test.

The existing clean llama.cpp build11909 / `caa8191df159f764fb0160e3d2fc6be008948aee`, its binary and ten native shared libraries were pinned. It ran explicit `--load-mode mmap --lazy-mode on`, 12,288 context, one sequence, 256/128 batch/microbatch, eight CPU threads, reasoning off, no MTP drafter and 1536 MiB GPU fit targets. Native fit placed weight computation across both GPUs and CPU-mapped weights. GPU model buffers were 9648.23/7718.25 MiB. This is not fully GPU-resident execution. The native log reported a 12,288-token slot and lazy reads of `per_layer_token_embd.weight` (27,465 MiB). The owned process had a read-only shared mapping of the SSD table shard spanning 28,800,139,264 bytes including page alignment. Physical NVMe transport was verified before launch. A point-in-time prefill `smaps` observation showed about182.02 MiB table RSS and zero table swap; that does not measure total system file-cache occupancy.

One actual DSH read, matching executed tool result and exact follow-up passed. The first request had5831 input tokens,42 output tokens and zero cached prompt tokens. Native prompt/decode times were57.448/1.407 s, giving101.50/29.14 tok/s. Client TTFT58.113 s includes tool-parser buffering. The whole tool/result/follow-up took63.55 s; owned unload took1.012 s, both GPUs returned to baseline and the reservation was released. Loading took approximately54 s and is excluded from inference timings. The follow-up reused context and is excluded from the table. These different models/precisions and speculative settings do not establish an equal-quality speed ranking.

The guards in the table remained active: RAM24/26 GiB, host2 GiB, GPU floor256 MiB/card,82 C and three bad two-second resource/telemetry samples. The trial reused the existing bounded Flash-family active swap policy128/160 MiB/s over30 s and15% full-memory PSI with three bad samples; it did not launch the disabled Strata IQ3 worker. Lifecycle captured59 rows at a median2.073 s: charged worker RAM peaked23.99 GiB, swap287.24 MiB, minimum host available26.98 GiB, GPU free minima1591/1510 MiB and temperatures<=55/39 C. Soft `memory.high` reclaim/throttle events numbered3367; hard-max/OOM/OOM-kill events stayed zero. A soft-limit event is not a guard violation. Charging of shared file cache affects reported worker RAM.

Loading full-PSI peaked23.58%; this policy has no separate loading-PSI stop. Active full-PSI peaked7.38%, and after complete30-second windows it stayed<=2.53%. Across15 complete active windows, write and combined swap rates peaked2.36/3.13 MiB/s, within128/160. No guard violation occurred. These are short-run observations, not a sustained swap or full-context qualification. The table is SSD-backed and lazy-read; OS file cache was not dropped, and publisher hashing preceded load, so cold-SSD speed is not established.

Two setup failures are retained. First, the model loaded but the supervisor stopped it before inference because default verbosity3 hid the native lazy-read proof. Source inspection showed library INFO maps to TRACE4; only log verbosity was corrected, preserving all memory settings/guards. Owned unload/release passed. Second, an immediate preflight bind encountered `TIME_WAIT` on the closed test port, with no live listener, no worker and no reservation created. The preflight probe now uses `SO_REUSEADDR`, which permits that closed-socket state while still rejecting a live listener. The corrected trial above is the sole successful short inference observation; no benchmark was replayed for a better number. One CPU adapter check covers native busy/deferred gauges, nonfinite/missing telemetry and unchanged bounded swap thresholds.

TensorFold remains a useful fast tool-burst entry on this host. Flash-Next IQ1_S is now proven viable for one guarded short tool round trip with the table on SSD; its roughly58-second first-tool latency is the main usability tradeoff in this observation. Existing profiles/defaults were preserved, and no fallback was preloaded after either test.
